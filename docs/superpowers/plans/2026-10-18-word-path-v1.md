# Word Path v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Word Path from scratch as Word Path Spec v1.0-rc1 describes it, with answers and clues sourced automatically by AI from the internet instead of an editor's files: rules engine, unique-route generator, word lists, AI content pipeline, and the playable site with a daily puzzle plus unlimited play.

**Architecture:** pnpm workspace. `packages/engine` is pure TypeScript (rules, route finder, generator, schemas), no DOM and no runtime deps. `tools/*` are Node CLIs that import the engine: one builds word lists, one builds and verifies puzzle files, one asks a proposer AI model (with web search) for new answers and clues, checks them with deterministic gates and a separate reviewer model, and writes puzzle files. `apps/web` is a Vite + React 19 site that fetches the static puzzle files and plays them with the engine. Browsers never generate puzzles and never call AI. A scheduled GitHub Action keeps 30 days of dailies ahead and adds new unlimited puzzles every day.

**Tech Stack:** Node ≥22, pnpm 10, TypeScript strict, Vite, React 19, Vitest (projects) + jsdom + Testing Library, fast-check, oxlint, tsx, Playwright + `@axe-core/playwright`, `@anthropic-ai/sdk` (tools/content only), GSAP + `@gsap/react` (apps/web only), GitHub Actions, Cloudflare Pages. Use latest stable versions at install time; the lockfile pins them.

**Spec:** [Word Path Spec v1.0-rc1](Tiny%20Trouble%20Games_%20Word%20Path%20Spec%20v1.0-rc1.md). Section numbers (§) below refer to it. Where this plan departs from it, the departure is listed under Decisions. Project rules: [CLAUDE.md](../../../CLAUDE.md) (rewritten on 2026-10-18 to match this plan; Task 25 updates it after the build).

## Decisions

**Confirmed by the user:** P1 answers whose reverse is a word are ineligible (rc1 §4.2 needs a one-line amendment: the reversed solution route would be a second route, so no valid grid exists). P2 the public file carries `checks`, an obfuscated solution route per size, so the browser can check routes and reveal the route on give up (§6.3 accepts local checking). P6 Give up asks "Give up? Yes / No" first. P9 Playwright and axe are dev dependencies. N1–N13 below. Old plan and design doc deleted.

**Changed by the user:** content is sourced by AI from the internet, with no editor and no answer files (P3, P4). No launch date and nothing that depends on one (P5). No sharing (P8). A second model reviews and blind-solves every clue (N1). Desktop gets a 15×15 board (N8). The game can be played many times a day (N9). No hints (N13). Stats stay in this browser only, with no sign-in (N14). Tiles are raised 3D clay pavers (N15). A petal-and-leaf burst celebrates a solve (N17). The hedgehog mascot is parked under Later developments (L1). Three difficulty levels: dailies are Normal; players pick Easy, Normal, or Hard for Unlimited on a Word Path page that opens from the Home card (N21); difficulty comes from twistier routes, more near misses, and harder clues, never from tile colors (N18–N20). Home shows a designed game card, not the game screen (N7). The UI is designed with `/impeccable`, `/emil-design-eng`, `/design-taste-frontend-v1`, and GSAP via `/gsap-skills:gsap-react` (N10, N11). Backend diffs get `/ponytail:ponytail-review` before each commit (N12).

## Global Constraints

- Node `>=22`, `packageManager: pnpm@10.x`, TypeScript `strict`. `packages/engine`: `lib: ["ES2022"]` only, zero runtime dependencies (enforces purity). Only `tools/content` may depend on `@anthropic-ai/sdk` or call the network for AI; engine and web never do.
- `rulesVersion = "wordpath/v1"`. After Task 25, `packages/engine/src/wordpath/v1/` is frozen; a rule change is a new `v2/` folder. Loaders refuse unknown versions.
- Sizes `SIZES = [6, 7, 8, 9, 10, 15]`: touch devices use 6..10; mouse devices use 15, or 6..10 when the window is too small (N8). Answers: 5–7 letters, ≥4 distinct letters, not palindromes, not proper nouns/abbreviations/offensive, in the answer list, reverse not in the blocking list (P1), never reused (N5).
- Grid: every cell holds one of the answer's distinct letters. Route: distinct orthogonally adjacent cells, length = answer length. Valid grid: exactly one route spells any word in T (answer + blocked words), and it spells the answer. Blocked words: every blocking-list word of the answer's length using only the answer's distinct letters, minus the answer.
- Generator: seed from (date or unlimited id, size, generator version `gen-1`); 12% random-letter chance in step 5; 3,000 changes per attempt; 1,000 attempts per size (N22); near misses planted to the level's minimum (N23); all six sizes must succeed. Quality: each distinct letter appears ≥ ⌈N²/(2k)⌉ times; the route has ≥1 turn; plus the puzzle level's route-shape and near-miss rules (`LEVEL_RULES`, N18). Dailies are `normal`.
- No hints (N13). Wrong word shown 0.9 s then route clears. No time limit, no attempt limit.
- Board size (N8): measured on the **board slot** (the space CSS gives the plot inside its hedge frame). Touch → N = largest of 6..10 with `N × 44px ≤ slot width`; tile = min(48px, width ÷ N). Mouse (`(pointer: fine) and (hover: hover)`) → N = 15 if `15 × 36px` fits the slot's width and height, else the largest of 6..10 with `N × 36px` fitting both; never below 6; tile = min(48px, width ÷ N, height ÷ N). N is locked per attempt and saved; only the tile follows later resizes. Media queries and measured sizes only, never the user-agent string.
- AI roles (N1): proposer and reviewer are different models; `createAnthropicLlm`, `createGeminiLlm` (N24), and `createOpenRouterLlm` (N25) throw at startup if they match.
- IDs/paths: daily `wp-<date>` at `data/public/wordpath/<date>.json` (served at `/wordpath/<date>.json`); unlimited `wp-u-<level>-<n>` at `data/public/wordpath/unlimited/<level>/<n>.json` (`n` = 1..count for that level), with `unlimited/index.json` = `{ "count": { "easy": number, "normal": number, "hard": number }, "started": "YYYY-MM-DD" }`. Keep ≥ `AHEAD_DAYS = 30` dailies ahead; each level's unlimited target = `UNLIMITED_INITIAL = 40` + `UNLIMITED_PER_DAY = 7` × days since `started` (N19). Public types never hold a plaintext answer field.
- Storage keys: daily `ttg:wordpath:active` and `ttg:wordpath:results`; unlimited `ttg:wordpath:unlimited-active:<level>` (one saved puzzle per level) and `ttg:wordpath:unlimited-results`; `ttg:wordpath:seen-howto`. Every read and write goes through `shared/storage.ts`; nothing leaves the browser (N14).
- Colors: tile brown `#7A4A2B` / maroon `#7A1F2E` checkerboard; letters cream `#FFF3E3`; selected orange `#F28C28` with text `#2B1400` + 2px outline; tiles are 3D pavers (N15) with side walls brown `#4E2D18`, maroon `#4C1019`, orange `#A9560F`, green `#1B4A2B`; circle = 84% of tap area; letter ≈39% of tile size.
- Accessibility: every action a single tap/click; arrows move focus, Enter/Space select, Escape clears, Tab reaches every button; cell labels `"M, row 2, column 3"`; live region for route and results; reduced motion → fades; never color alone.
- Secrets: `OPENROUTER_API_KEY` (N25) / `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` (N24) only from the environment, never written to a file or log.
- Frontend (N10, N11): before any UI edit, load `/impeccable` (it loads the project context and its craft floor) and follow the D1 direction contract; use `/emil-design-eng` for motion and component details; write GSAP only with `useGSAP` plus a `scope` ref, wrap event-time tweens in `contextSafe`, no unscoped selectors (`/gsap-skills:gsap-react`). Animate only `transform` and `opacity`. No emoji anywhere. The petal burst is decorative (N17): `aria-hidden`, skippable, absent under reduced motion. No mascot in v1 (L1). No icon, CSS framework, or font CDN dependency.
- Backend review (N12): after a task's tests pass and before its commit, run `/ponytail:ponytail-review` on the task's diff, apply each `delete`/`stdlib`/`native`/`yagni`/`shrink` finding that keeps the tests green, re-run the tests, and name any skipped finding with a one-line reason in the commit body.

## Review Focus

1. **Answer whose reverse is a word (STRAP/PARTS) or a palindrome** → rejected up front with a clear reason, and the AI is asked for another; nothing is written (Tasks 5, 7, 10, 11).
2. **AI returns junk: invalid JSON, a dead or non-HTTPS source URL, a page that never mentions the answer, an unsupported or offensive clue, a clue the reviewer cannot solve or solves as a different word, or a word already used** → never published, retried with the reason fed back, reported when out of tries (Tasks 10, 11).
3. **Puzzle started before midnight, resumed after** → same puzzle, result recorded under the start date, streak uses that date (Task 20).
4. **Corrupt or blocked localStorage** → data discarded silently, game still plays (Tasks 14, 17, 20).
5. **Static host answers a missing puzzle with `index.html` and status 200** → friendly "No Word Path puzzle today" (Task 16).

### Task 7: Generator (§5.2)

**Files:** Create `v1/generate.ts`, `generate.test.ts`; append to `v1/index.ts`.

**Interfaces:**
- Consumes: `rngFrom`/`randInt`/`shuffle`, `neighbors`, `sameRoute`, `findRoutes`, `qualityProblems`, `reverse`.
- Produces: `GENERATOR_VERSION = 'gen-1'`, `seedFor(key: string, size: number): string` (`` `${key}|${size}|${GENERATOR_VERSION}` ``; `key` is a date or unlimited id), `interface GenerateInput { answer: string; size: number; level: Level; blocked: readonly string[]; seed: string; maxChanges?: number /*3000*/; maxAttempts?: number /*1000, N22*/ }`, `interface Generated { cells: string; solution: number[]; attempts: number }`, `class GenerateError extends Error` (message names answer, size, and cause), `generate(input: GenerateInput): Generated`.

Algorithm per attempt (`rng = rngFrom(seed)`, one rng across attempts):
1. Fill every cell with a random letter of the answer's distinct letters.
2. Pick a random self-avoiding walk of the answer's length (backtracking, shuffled neighbors) whose shape meets the level (`turns` and `longestRun` against `LEVEL_RULES`; redraw up to 50 times, else abandon the attempt); write the answer on it; lock those cells.
3. Loop up to `maxChanges` times: `routes = findRoutes(size, cells, [answer, ...blocked])`. If exactly one (the locked one), go to 5. Else pick a random route ≠ the locked one; if it has no unlocked cell, abandon the attempt. Pick a random unlocked cell on it; with probability 0.12 set it to a random letter, otherwise to the letter (≠ current) that leaves the fewest routes (ties broken randomly).
4. Exceeding `maxChanges` abandons the attempt.
5. **Plant near misses (N23).** While the grid has fewer near misses than the level needs, write `answer` minus its last letter on a random self-avoiding path of L−1 cells that avoids the solution, then run the step-3 loop (planted cells held fixed) on the remaining change budget. Keep the plant if the grid has one route again; otherwise restore the grid from before the plant. Stop after a bounded number of plants.
6. If `qualityProblems(..., level)` is non-empty (letter balance or near misses; the shape already passed in step 2), abandon the attempt; else return.

Refuse before any work (throw `GenerateError`): palindrome; `reverse(answer)` is in `blocked`.

### L1: Hedgehog mascot

A mascot: a small **low-poly hedgehog** (it lives in the hedge maze), authored as one SVG (≤ 8 KB) with poses `sit`, `walk`, `ball`, `sleep`. It reacts only to events, never idles: on a solve it trots along the route stone by stone and sits on the last tile; on a wrong path it curls into a ball and rolls, then uncurls inside 0.9 s; on Home it sits on the card's example board and walks the example path on hover or focus; it demonstrates the path in How to play; it sleeps in the empty plot on the no-puzzle screen. On wide screens it sits beside the board while playing; on phones it appears only once the puzzle is solved. Always `aria-hidden`, never blocks input. The preview's hedgehog is placeholder art.

Why it was proposed: User asked for small animal 3D animations or mascots that look premium and engage players. A real 3D model (Three.js/WebGL) would add a ~150 KB dependency, a licensed model, and GPU cost on every screen; a faceted low-poly SVG reads as 3D at a fraction of that. Kept small, in the garden palette, with no speech bubbles or idle loops, so it stays grown-up (PRODUCT.md: not childish).
